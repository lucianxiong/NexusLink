# 完整配置模板（sing-box）

「完整配置模板」是给 sing-box 内核的整份配置接管，供高级用户使用。启用后，应用不再使用自己生成的路由、DNS 等配置，一切由你的模板决定；应用只负责把自己的节点出站追加进去。

本应用只随附 sing-box 内核，因此只有 sing-box 一栏模板。

入口：应用内的「完整配置模板设置」窗口（勾选「启用完整配置模板」后生效）。

> 注意：当前发布版本的界面**没有打开这个窗口的入口**（代码保留）。本文说明的是代码的实际行为，供源码使用者与后续开放该入口时参考。

## 应用具体做了什么

1. 模板已启用、且内容能解析为 JSON 时才生效；解析失败则忽略模板，继续使用应用自动生成的配置。
2. 应用把当前配置生成的出站**追加到模板 `outbounds` 数组的末尾**，模板里原有的出站保留：
   - 勾选「不添加非代理协议出站」时，应用生成的 `direct`、`block` 出站不再追加，需要你的模板自带。
   - 「设置上游代理 tag」不为空时，每个节点出站会被加上 `"detour": "<你填写的出站 tag>"`（服务器地址是内网地址的出站除外）。
3. 开启 TUN 模式时改用 TUN 专用的模板内容，机制相同。
4. 应用的端点（`endpoints`，例如 WireGuard）同样追加到模板的 `endpoints` 数组，`detour` 规则一致。

模板的字段与格式遵循 [sing-box 官方文档](https://sing-box.sagernet.org/zh/configuration/)。

## 追加进来的出站标签

| 当前使用的节点 | 应用追加的出站 tag |
| --- | --- |
| 单个节点 | `proxy` |
| 畅连·自动优选（策略组） | `proxy`（选择器）、`proxy-auto`（内核自测速组）、`proxy-N-节点名`（各成员节点） |

路由里用 `"final": "proxy"` 引用即可（策略组同理，`proxy` 就是选择器）。

## 需要你自行保证的部分

- **入站端口**：模板里的入站端口要与「参数设置」里的本地监听端口一致（默认 `10808`），否则系统代理指向的端口没有服务。
- **Clash API**：节点管家的自动切换、网速显示都依赖内核的 Clash API。模板未配置 `experimental.clash_api` 时，这些功能不可用。
- DNS、路由、流量统计等全部按你的模板生效。

## 最小示例

```json
{
  "log": { "level": "warn" },
  "inbounds": [
    {
      "type": "mixed",
      "tag": "mixed-in",
      "listen": "127.0.0.1",
      "listen_port": 10808
    }
  ],
  "outbounds": [
    { "type": "direct", "tag": "direct" },
    { "type": "block", "tag": "block" }
  ],
  "route": {
    "rules": [
      { "ip_is_private": true, "outbound": "direct" }
    ],
    "final": "proxy"
  }
}
```

说明：示例中没有 `proxy` 出站，它由应用在启动内核前追加；上面没有配置 DNS 与 Clash API，仅演示模板的接管方式，实际使用请按需补全。
